P6 and the implementation/package portion of P7 are delivered by [PR #4](https://github.com/wegamekinglc/dal.jax/pull/4), following P5 in PR #3. The alpha version is `0.1.0a1`. PyPI upload is deferred; the wheel, source distribution and manual publication workflow are prepared.

## Bermudan valuation

An exercise product uses three disjoint Sobol intervals. Phase A simulates hard script events and records event payments, exercise values, conditions, numeraires and regression features. Phase B walks backwards through those records, fitting continuation values in event-date currency units. Phase C prices fresh paths with the fitted policy. A hard exercise stops later events and replaces that day's payment with the exercise value. Fuzzy pricing blends exercise and holding values using the script's smoothing width.

```python
import jax
import dal_jax as dj
from dal_jax.api import Product_New
from dal_jax.dates import Date

today = Date.ymd(2026, 10, 8)
product = Product_New(
    ["K", today.add_days(180), today.add_days(365)],
    ["100", "EXERCISE MAX(K-SPOT(),0)", "EXERCISE MAX(K-SPOT(),0)"],
)
model = dj.BlackScholes(spot=100., vol=.2, rate=.03, div=0.)
prepared = dj.prepare(product, today, model=model)
settings = dj.MonteCarloSettings(
    enable_aad=True, use_bb=True, lsmc_training_paths=4096,
    lsmc_validation_paths=1024, lsmc_basis_degree=3,
)
engine = prepared.engine(model, settings)
result = engine.value(2**16)

# Train once, then compose JAX transforms around this fixed policy.
params = engine.default_params()
policy = engine.train(2**16, params)
price = engine.pricer(2**16, policy=policy)
pv, risks = jax.jit(jax.value_and_grad(lambda p: price(p)[0]))(params)
```

Use `prepared.engine(model, settings)` for exercise scripts. `MonteCarloEngine(prepared.path_product(), model, settings)` is the ordinary payoff route. The compatibility API's `MonteCarlo_ValueWithSettings` chooses the engine automatically.

`engine.train` returns a `Policy` containing passive coefficients and normalization arrays. `engine.pricer` trains once when no policy is supplied; subsequent calls reuse that policy even if parameters change. `engine.value` trains at the supplied parameters on every call and reuses compiled executables when shapes stay fixed. Pricing remains blocked and checkpointed; phase A materializes training records, so its memory grows with training paths and event count.

For diagnostics, use `evaluated = engine.evaluate(n_paths)`: `evaluated.as_dict()` contains prices and risks, `evaluated.training.regressions` contains fits, and `evaluated.replicate_means` contains replica prices. `engine.train_result(...)` returns a policy and fits together. These immutable results survive later training; the engine no longer keeps mutable last-result fields. Build `engine.training_pricer(...)` before transforming device training. [The user guide](user-guide.md) covers explicit valuation contexts and migration.

## Regression and risk conventions

Scalar regression uses normalized monomials, degrees 1–8, float64 masked moments, a relative diagonal ridge of `1e-12`, and a small host Cholesky solve. The unregularized Gram matrix is checked for rank and scale first. Rank loss uses scaled, column-pivoted, twice-reorthogonalized QR and can reduce the degree. Insufficient eligible paths or negligible feature variation use a constant policy. Diagnostics expose the actual degree, solver, rank and fallback reason.

Two or three features use DAL's ordered total-degree basis through degree 3 and pivoted QR. Normalization preserves DAL's ordered Welford moments: CPU arrays use a masked scan, while GPU arrays retain host normalization because its measured device scan was slower. This compatibility path transfers included feature rows to the host for QR; scalar regression usually transfers only moments and the small system. `RetrainedBump` uses fixed-shape JAX regression and `vmap` to train the parameter bumps together.

Set `ScriptProductSettings(regression_features=(...))` to select supported equity/rate indices or scalar script state, for example `("EQ[A]", "IR[USD,LIBOR_3M_CME]", "VAR[average]")`. Features are captured at the exercise statement. Single-equity products default to `SPOT()`. Multi-equity products need a default index or explicit features; rate-only products need explicit features. Exercise dates must be strictly after the valuation date. The selected payoff receiver permits only zero initialization and additive payments.

With `lsmc_validation_paths`, candidates are compared on held-out paths. The smallest candidate within one standard error of the best validation loss is selected. Empty validation masks retain the requested fit. Validation paths follow training paths; pricing starts after both.

| Setting | Meaning |
|---|---|
| `lsmc_training_paths=None` | Train on as many paths as each pricing replica |
| `lsmc_basis_degree=3` | Maximum regression degree |
| `lsmc_validation_paths=None` | No held-out degree selection |
| `lsmc_rqmc_replicates=None` | One deterministic Sobol pricing interval |
| `lsmc_rqmc_replicates=R` | At least two independent digital-shift pricing replicas |
| `lsmc_training_seed`, `lsmc_pricing_seed` | Nonnegative 31-bit seeds, used only with RQMC |
| `lsmc_policy_risk_mode="Frozen"` | Differentiate prices with passive policy and normalization |
| `lsmc_policy_risk_mode="RetrainedBump"` | Add DAL's policy-risk secant correction to frozen risks |
| `lsmc_policy_bump_relative=1e-3` | Parameter bump is this fraction of `max(1, abs(parameter))` |

`RetrainedBump` reprices bumped policies at **base model and script inputs**. It adds that policy-price secant to the frozen derivative; it is not a finite difference of the entire bumped valuation. A constrained lower bump uses a one-sided correction. Model validation rejects invalid upper bumps. The mode requires AAD.

RQMC trains one common policy using key `training_seed << 32`. Pricing replica `r` uses `(1 << 63) | (pricing_seed << 32) | r`, with a separate pricing interval for every replica. Both match DAL's SplitMix64 digital-shift convention. Reported uncertainty is conditional on the trained policy; it excludes training uncertainty. Only Sobol is supported for exercise valuation, and the combined intervals must fit the 32-bit sequence.

## Rate models and observations

`GSR` accepts `GSRVol` or `MultiFactorGSRVol`. Curves use ACT/365 times and log-linear dated discount/projection factors. Piecewise constant `g` and `H` are integrated over their own knots. Gaussian state and bank-account increments use DAL's covariance construction, including singular positive-semidefinite factor correlations and zero-volatility derivatives.

```python
from dal_jax.api import GSRCurveData_New, GSRVolData_New, GSRModelData_New

curve = GSRCurveData_New(
    "curve", today, "USD", [today, today.add_days(365*8)], [0., -.24],
)
vol = GSRVolData_New("vol", [today], [.02], [today], [1.])
rates = GSRModelData_New("rates", curve, vol)
coupon = Product_New([today.add_days(365)],
                     ["pay PAYS FIX(IR[USD,LIBOR_3M_CME])"])
value = dj.prepare(coupon, today, model=rates).engine(rates).value(4096)
```

Supported future observations are domestic-currency DF, Libor and swap indices. Libor projection curves are optional; the discount curve supplies the fallback. Index start dates, calendars and coupon accruals follow DAL's script conventions. Dated GSR observation times and required bond maturities must lie in the curve domain. The curve evaluation date must match the script valuation date.

`GSRSLV` adds a full-truncation variance process and a positive bilinear leverage surface to a multi-factor Gaussian model. Its integration grid includes sample dates, rate/leverage knots and `max_step` subdivisions. The numeraire includes the correlated rate integral and an independent bridge driver. All curve, `g`, `H`, leverage, `kappa` and `volOfVol` parameters have risk labels. Correlations, dates and grid topology are passive.

Gaussian GSR supports delayed `PAYS ... ON` discount factors. GSRSLV and hybrids containing GSRSLV reject delayed payments, matching the native model capability. They still support ordinary domestic DF observations.

## Domestic hybrids

`HybridModelData_New` combines named BS or local-volatility equity components with exactly one domestic rate component: a flat rate, a log-discount curve, Gaussian GSR or GSRSLV. All components use the same currency; this alpha does not implement stochastic FX, foreign numeraires or calibration.

`HybridCorrelation_Assemble` installs each component's internal correlation block and accepts explicit `HybridFactorLink_` cross-links. Factors are sorted by DAL's case-insensitive names and a supplied matrix is reordered to that registry. Hybrid correlation must be positive definite. Gaussian rate blocks must match their kernel; the SLV bridge factor remains independent. Components, observables and factors must have unique names.

The dated grid includes rate/leverage knots and equity maximum steps. The domestic bank account is advanced before equity carry is applied. Gaussian hybrids include an auxiliary rate-integral bridge dimension. Log-discount curves support `LOG_LINEAR`, `LOG_CUBIC_NATURAL` and `MIXED`, with the native end-secant extrapolation. Every equity spot/dividend/volatility or local-vol node and every active rate parameter is differentiated.

Rate volatility is an active parameter. A Gaussian/SLV hybrid chooses its bank-account route from live `g` parameters; changing them through a reused pricer must match constructing a fresh model. All-zero live `g` values retain DAL's deterministic-numeraire risk convention. Deterministic flat/log-curve rate components keep their deterministic route.

See [example 15](../examples/15_gsr_rates.py) for single/multi-factor rate construction and rate exercise, and [example 16](../examples/16_gsr_slv_hybrid.py) for SLV and named equity/rate correlation assembly.

## Diagnostics and migration

`ScriptValuation_Explain(product, model, valuation=...)` returns schema `dal.script-valuation/1`: observation uses with source locations, historical resolutions, model bindings, sample dates, event/sample mapping and output/discount slots. Exercise liveness removes dead model outputs while preserving dates and Sobol dimension. Historical resolution and index validation occur before pruning.

`ScriptSimulation_Explain(..., simulation=...)` returns schema `dal.script-simulation/1`: regression normalization, coefficients, degree, solver, rank, validation loss, first-exercise rates and conditional-policy uncertainty. It streams replay statistics rather than returning all pricing paths. This diagnostic requires `enable_aad=False`; a plain or expired product reports uncertainty as not applicable. [Example 14](../examples/14_lsmc_validation_rqmc.py) compares native replica means and retrained-policy Greeks.

The factories and compatibility settings are in `dal_jax.api`; immutable native model classes are in `dal_jax.models`. Replace `import dal` with `import dal_jax.api as dal` for factory-based code, retaining Python `Date` values or ISO date strings. Use `dj.MonteCarloSettings` for execution options. `MonteCarloSettings_` also accepts DAL's `method` and `compiled` names; `compiled` warns and is ignored because XLA performs compilation. Snapshot mutable `GSRSLVSettings_` inputs through the model factory.

Changing grid dates, path shapes or static settings may compile a new executable. Reuse the prepared engine for repeated valuations. CPU device count must be configured before the first JAX operation. Float64 remains the CPU/GPU compatibility default. Float32 hybrid cases have separate GPU tolerances; narrow fuzzy transitions and exercise boundaries still require product-specific validation. The existing [precision report](performance.md#precision-and-reproducibility) explains the observed limitations.

## Validation and performance

The reference is DAL source commit `4feabe89b105e0a3883fd4e2d74a2d70d618d8c7`, built using [the oracle helper](../scripts/build_dal_oracle.sh). The older published `dal-python` package lacks these factories and regression settings; those comparisons are skipped there and required by the pinned-native CI job. Native tests cover scalar and multivariate fits, degrees through 8, held-out selection, vector state, historical risks, RQMC replica means, policy bumps at parameter constraints, curve/projection risks, singular Gaussian factors, all hybrid kernels and full diagnostic schemas.

Regular Sobol comparisons require PV relative error `1e-10`, Greek relative error `1e-8` and near-zero absolute error `1e-10`. LSMC coefficients use relative error `1e-8`; LSMC PV uses `1e-6` because hard decisions can flip on boundary paths. CPU tests also check forward/reverse derivatives, common-path finite differences and all four parallel strategies. Actual RTX 4060 Laptop GPU tests compare CPU/GPU/native prices and all risks, including bridge on/off, RQMC, retraining and float32 hybrids.

The pinned native source has an AAD defect for the spot risk of a zero-rate-volatility SLV hybrid. For the two-date call/coupon fixture with 257 paths, native AAD reports `85.5575912`; its own common-path spot finite difference and JAX both give `1.065581856`. The zero-SLV CPU/GPU tests compare this risk against native finite differences and every other risk against native AAD. Nonzero SLV cases retain full AAD parity.

CI checks complexity across source, tests, examples and benchmarks, plus Python errors and Bandit/Semgrep security patterns. The separate nightly workflow upgrades both JAX packages from the [official nightly index](https://docs.jax.dev/en/latest/installation.html#jax-nightly-installation) and runs the CPU suite directly, preserving the alpha's stable runtime dependency constraint.

Measured results and reproduction commands are in [the P6/P7 performance report](p6-p7-performance.md). Timings separate compilation, training, frozen-policy pricing and complete valuation. Native DAL times include training on each call.

## Build and publish later

```bash
uv build
uvx twine check dist/*
uv venv /tmp/dal-jax-alpha --python 3.13
uv pip install --python /tmp/dal-jax-alpha/bin/python dist/*.whl
/tmp/dal-jax-alpha/bin/python scripts/smoke_install.py
```

The wheel has only JAX and NumPy as direct runtime requirements; SciPy is a transitive JAX dependency. DAL is needed only for comparisons. The source distribution includes tests, examples, scripts, docs, license and changelog.

The CI distribution job uploads the validated wheel, source distribution and `SHA256SUMS` as the `dal-jax-distributions` artifact. Local builds remain in `dist/`.

The manual [release workflow](../.github/workflows/release.yml) builds and validates distributions, then publishes using PyPI Trusted Publishing. Configure owner `wegamekinglc`, repository `dal.jax`, workflow `release.yml` and environment `pypi` on PyPI before dispatching it at the approved release commit. Alternatively, `uv publish` can use a securely configured `UV_PUBLISH_TOKEN`. This change prepares the artifacts and workflow; it does not upload to PyPI.
